GRIDIRON BRACKET BOX — DESIGN DECISIONS LOG
(Append-only. Format: date — what — why.)

2026-10-22 — Installed .NET 10 SDK (10.0.402) and Git via winget. — No SDK was present; .NET 10 is the current LTS.
2026-10-22 — Use Avalonia 12.1.4 (not 11.3 as first planned). — It's what the current official templates generate; newest stable.
2026-10-22 — Three projects: Core (logic), app (UI), Tests (xUnit). — Keeps bracket logic UI-free so it can be unit-tested for every size/mode.
2026-10-22 — MVVM with CommunityToolkit.Mvvm (template default). — Standard Avalonia pattern; less boilerplate than ReactiveUI for a beginner to read.
2026-10-22 — Force dark theme (RequestedThemeVariant="Dark") with Fluent theme. — Spec asks for a clean, modern dark theme regardless of OS setting.
2026-10-22 — Bracket stored as setup (teams+seeds) + list of picks; rounds derived by re-seeding. — One general algorithm for all sizes; undo/change = drop dependent picks.
2026-10-22 — Conference mode: teams restricted to their conference, seeds 1..N/2 each; final is always AFC champ vs NFC champ. — Mirrors real NFL format.
2026-10-22 — Git used for a checkpoint commit after each stage. — User approved installing git.
2026-10-22 — Picks stored as (round, winner, loser) records, not slot positions. — With re-seeding, slots move; a pick stays valid only if that exact matchup still exists, so changing an early result auto-clears just the later picks it affected and keeps the rest.
2026-10-22 — Next round's matchups appear only after every game in the current round is decided. — NFL re-seeding needs all results first; partial rounds show "TBD" slots.
2026-10-22 — Conference mode: picks in one conference never clear the other's (only the Super Bowl if a champion changes). — Conferences are independent brackets.
2026-10-22 — Undo is a snapshot stack of the pick list; Reset is also undoable. — Simple and covers every change type (pick, change, clear, reset).
2026-10-22 — Re-picking the current winner is a no-op (no undo entry). — Avoids "empty" undo steps from accidental double clicks.
2026-10-22 — Round names derived from size (Wild Card / Divisional / Conference Championship / Super Bowl; open mode uses Round of N / Quarterfinals / Semifinals). First round is "Wild Card Round" whenever byes exist. — Matches NFL naming without hard-coding per bracket.
2026-10-22 — Open-mode final is also called "Super Bowl". — It's still the NFL title game, just without conferences.
2026-10-22 — ByeRules.Validate() + tests guarantee every rule yields a power-of-two field after round 1. — Protects future edits to the bye table.
2026-10-22 — Tests: 118 xUnit cases incl. full tournaments (favorites, underdogs, 25 random) for all 10 size/mode combos, verified by deliberately breaking re-seeding (tests failed as expected, then restored). — Proves the tests actually catch bugs.
2026-10-22 — Replaced the template's reflection-based ViewLocator with explicit DataTemplates in App.axaml. — Reflection lookups can break in trimmed/single-file builds; explicit mapping is also easier to read.
2026-10-22 — Navigation: MainViewModel.CurrentPage swaps between SetupViewModel and PlayViewModel; the setup VM is kept so "Back to setup" preserves choices. — Simple screen switching without a navigation framework.
2026-10-22 — Seeding UI: click a team to append it to its seed list; list position = seed; ▲/▼ reorder, ✕ removes. — Makes duplicate/missing seeds impossible instead of validating typed numbers after the fact.
2026-10-22 — Changing mode/size keeps picks: conference→open interleaves AFC1, NFC1, AFC2…; open→conference splits by conference; overflow is trimmed from the bottom. — Avoids losing work when experimenting with settings.
2026-10-22 — Setup buttons: Quick fill (fills empty seeds in list order), Shuffle seeds, Clear all; Start only enabled when BracketSetup.Validate() passes. — Fast way to try brackets; Core validation stays the single source of truth.
2026-10-22 — Default setup screen: 14 teams, Conference mode. — Matches the current real NFL format.
2026-10-22 — Palette: AFC red #E5484D, NFC blue #3E8EF7, bye gold #F2B33D, accent/winner green #16A34A/#22C55E on navy-black background. — Conference colors are instantly recognizable; green reads as "go"/winner.
2026-10-22 — AFC/NFC tag on seed rows shown only in open mode. — Redundant in conference mode (column header says it) and it squeezed team names.
2026-10-22 — Added Bracket.ByeTeams(section) to Core (+10 tests, 128 total). — Play screen shows bye teams in the first-round column so they don't vanish until round 2.
2026-10-22 — Play screen layout: one column per round; conference mode = AFC rounds → Super Bowl → NFC rounds mirrored; open mode = left to right. — Classic bracket shape with the title game in the middle.
2026-10-22 — No connector lines between rounds; later-round games are vertically centered in equal-height columns instead. — With NFL re-seeding, winners don't follow fixed paths, so fixed lines would point to the wrong game.
2026-10-22 — Click = pick winner; click the other team = change; click the winner again = clear. Undo button + Ctrl+Z; Reset is undoable. — Covers "undo or change a pick" with no extra dialogs.
2026-10-22 — Notice line tells the user how many later picks a change cleared and that Undo restores them. — Auto-clearing downstream picks shouldn't be silent.
2026-10-22 — Play view models are rebuilt from Core after every change (not patched in place). — Screen can never drift out of sync with bracket logic; max 31 games so cost is trivial.
2026-10-22 — "Fit to window" toggle (on by default) scales the whole bracket down via Viewbox; off = full size with scroll bars. — 7–9 columns (conference) or 16 first-round games (open 32) don't fit a 1280px window otherwise.
2026-10-22 — Scroll-bar settings moved from attributes into styles. — In Avalonia a value set directly on a control beats any style, which silently blocked the fit-mode style (found in testing).
2026-10-22 — Notice/help/champion banner live in a fixed-height strip; banner overlays the help text. — Testing showed the bracket jumping down when the notice/banner appeared, which made clicks land on the wrong team.
2026-10-22 — Champion shown as a gold banner; championship card gets a gold border. — Clear "tournament over" moment.
2026-10-22 — Added "Randomize" button on the setup screen (user request): replaces all picks with random teams in random seed order for the selected size and mode. — Fast way to generate fresh brackets.
2026-10-22 — Random logic lives in Core as BracketSetup.Randomize(mode, size, rng); conference mode draws N/2 per conference, open mode draws from all 32. Optional seeded Random for repeatability. — Keeps it unit-testable: +21 tests (149 total) verify 50 random setups per size/mode are valid and playable, results vary, and a fixed seed is repeatable.
2026-10-22 — Randomize replaces (not fills) existing picks; Quick fill still fills only empty seeds. — Two distinct behaviors: "start over randomly" vs "finish my list".
2026-10-22 — Changing playoff size now clears all selected teams (user request); changing mode still carries picks over. Supersedes the earlier "size change keeps picks" behavior. — A new size is a fresh bracket; the user only asked for size, so mode switching keeps its convenience.
2026-10-22 — Mouse drag-and-drop on the setup screen (user request): drag a seed row to reseed it (list reorders live under the mouse, BYE badges follow), or drag a team from the picker onto the seed list to insert it at a specific seed (ghost label follows the mouse). Click-to-add and ▲ ▼ ✕ still work. — Faster, more natural reseeding.
2026-10-22 — Implemented with plain pointer events + pointer capture in SetupView code-behind, not Avalonia's DragDrop API. A press only becomes a drag after 6px of movement. — Everything happens inside one window; manual tracking is simpler, avoids the DragDrop API that changed in Avalonia 12, and keeps normal clicks working.
2026-10-22 — In conference mode a dragged team always lands in its own conference's list, wherever on the seeds card it's dropped. — Keeps the AFC/NFC split valid without error messages.
2026-10-22 — Bug found in testing and fixed: releasing pointer capture on every mouse-up broke all buttons on the setup screen (the button lost the mouse before it could click). Capture is now released only after a real drag. — Caught by the scripted click test before commit.
2026-10-22 — Seed rows: added ≡ grip, hand cursor, green highlight while dragging, full-name tooltip; tightened column spacing and icon-button width. — Grip column had squeezed team names to "…".
2026-10-22 — Drag visuals (user request: "see the team as you're dragging it", rows snapped with no animation): a tilted, shadowed "ghost" card follows the mouse (kept at the grab point) showing the seed it would land at; the row's original spot becomes a faded placeholder; on release the card glides into its slot. Picker drags also show a green insertion line and "+"/"FULL" when off-target/full. — Makes it obvious what's being moved and where it will land.
2026-10-22 — Row sliding via a reusable attached behavior, AnimateReorder (FLIP technique: compare layout positions after each pass, offset rows back to where they were, animate the offset to zero; new rows fade in). — Because it watches layout rather than specific actions, ▲ ▼, Shuffle, Randomize, click-add and drag all animate with no per-feature code.
2026-10-22 — Tooltips disabled during a drag. — Tooltips are small pop-up windows that appear under the cursor mid-drag; noisy at best.
2026-10-22 — Testing note: a drag "stall" seen during testing was a bug in the throwaway test script (PowerShell variables are case-insensitive, so $x overwrote $X), found with temporary logging; the app code was fine. Logging removed. — Recorded so it isn't chased again.
2026-10-22 — Windows packaging done before save/load (user request). build-windows.ps1 runs tests, then publishes win-x64 to dist\windows\. — Tests gate the package so a broken build is never shipped.
2026-10-22 — Packaging settings (SelfContained, PublishSingleFile, IncludeNativeLibrariesForSelfExtract, EnableCompressionInSingleFile, DebugType=none) live in the app .csproj, conditioned on a RuntimeIdentifier being set. — Plain `dotnet run`/`build` unaffected; the same settings will serve linux-x64 for the AppImage.
2026-10-22 — No trimming (PublishTrimmed off). — Trimming can silently break XAML/reflection in Avalonia apps; 47 MB compressed single file is acceptable.
2026-10-22 — Build script deletes stray .pdb debug files (Skia/HarfBuzz/Core) from the output. — ~100 MB of files not needed to run; output is now exactly one .exe.
2026-10-22 — Custom app icon (gold bracket + football on the dark tile), generated as a multi-size .ico (16–256 px) plus a 256 px PNG for the Linux AppImage; replaced the template's Avalonia logo. Product name/version set to "Gridiron Bracket Box" 1.0.0. — The exe should look like its own app in Explorer/taskbar.
2026-10-22 — Verified: the single .exe copied alone into an empty folder launches and plays a bracket. — Proves it is truly self-contained.
2026-10-22 — Save/load format: indented JSON with "format": "gridiron-bracket-box" and "version": 1, mode/size, teams (abbr+seed), picks (round/winner/loser), savedAt. Enums written as words. — Human-readable in any text editor; format/version lets the app recognize its files and reject newer ones clearly.
2026-10-22 — Only setup + picks are stored; rounds, matchups and champion are re-derived on load. Picks that no longer fit a matchup are silently dropped (same rule as editing). — One source of truth; a hand-edited file can't create an impossible bracket.
2026-10-22 — BracketFile lives in Core with a BracketFileException carrying user-readable messages (+17 tests, 166 total: save→load round trip for all 10 size/mode combos with random partial picks, bad JSON, foreign JSON, newer version, invalid teams, stale picks, missing picks). — Testable without the UI.
2026-10-22 — File dialogs behind an IFileDialogs interface (implemented by AvaloniaFileDialogs). — View models stay free of Avalonia windowing code.
2026-10-22 — One Save and one Open command (MainViewModel), shared by the play-screen buttons, the setup screen's "Open saved bracket…", and Ctrl+S / Ctrl+O window shortcuts. Save is only enabled on the play screen. — Single behavior everywhere.
2026-10-22 — Opening a file also loads its teams into the setup screen. Save suggests "bracket-<size>-<mode>-<date>.json", or the current file name after the first save/open (shown in the header). — "← Setup" and re-saving behave as expected.
2026-10-22 — Feedback via a pop-up toast at the bottom of the window (green 4 s; red 8 s for errors) instead of dialogs. — Non-blocking; a failed open leaves the current bracket untouched.
2026-10-22 — No "unsaved changes" warning on close/open (not requested). — Keeps the scope small; easy to add later if wanted.
2026-10-22 — Avoid new emoji in UI text (used "File:" not 📄). — Linux systems may lack an emoji font; 🎲 and 🏆 already in use should be checked on Arch.
2026-10-22 — Verified end-to-end with the real Windows Save/Open dialogs: save → clear → open restores picks and re-seeded rounds; a non-bracket JSON shows a red error and leaves the bracket intact. Windows exe rebuilt.
